# 自测清单（给接收方 agent）

> 这个技能包交给你做验收测试。按顺序跑，全部通过才算装好。
> **不要修改 `_internal/`、不要升级/降级依赖版本、不要把模型上传到任何在线服务。**

## 0. 先判断本包是哪种形态

| 包根目录里有 | 形态 | 本清单里的 `CLI` 指 |
|---|---|---|
| `patent-cli.exe` + `_internal/` | A 自包含版 | `patent-cli.exe` |
| 只有 `scripts/` + `install_deps.py` | B 轻量版 | `python scripts/patent_cli.py` |

> 下文所有命令里的 **`CLI`** 请按上表替换成你这一版的调用方式。
> 例：A 版写 `CLI --help` → 实际执行 `patent-cli.exe --help`；
> B 版写 `CLI --help` → 实际执行 `python scripts/patent_cli.py --help`。

B 版先装依赖（详见 `INSTALL.md`）：

```bash
python install_deps.py          # 只装缺的，OCP 约 91MB
python install_deps.py --check  # Python + 四个包全 ✓ 才算成功
```

> ⚠️ `python scripts/patent_cli.py --help` 能打印帮助**不代表依赖装好了**——
> OCP 是延迟导入的。判定一律以 `install_deps.py --check` 为准。

## 1. 命令行能起来

```bash
CLI --help
```

期望：列出 `auto / analyze / render / dxf / check / run / config` 七个子命令，退出码 0。
`--mode {one_shot,custom}` 必须出现在参数列表里。

## 1.5 准备一个 STEP 模型

自测需要任意一个 `.step` / `.stp` 文件。

- **A 版（一键包）**：自带 `examples/powerbank.step`，直接用
- **B 版（轻量版）**：包里不带示例（SkillHub 拒收 `.step`），先下载一个：

```bash
python -c "import urllib.request;urllib.request.urlretrieve('https://raw.githubusercontent.com/felix-lius/design-patent-views/main/examples/powerbank.step','powerbank.step')"
```

> 下文用 **`<模型>`** 指代你的 STEP 文件路径：
> A 版填 `examples/powerbank.step`，B 版填 `powerbank.step`。

## 2. 模式闸门：不选模式就什么都不做（核心验收项）

```bash
CLI auto --step <模型> --quiet --json-out m.json
```

期望：

- 退出码 **2**（需要用户输入，不是报错）
- `m.json` 里 `"need": "mode"`，`options` 是两项（`one_shot` / `custom`）
- **磁盘上不新增任何文件**：没有 `output/`、没有 `logs/`、没有预览图

> 这一项是 v1.0 那次事故的直接补丁。旧版这里会直接开跑，用户从没被问过。

## 3. 一键式出图（核心验收项）

```bash
CLI auto --step <模型> --mode one_shot --quiet --json-out out.json
```

期望：

- 退出码 **0**，`"ok": true`
- `"mode": "one_shot"`，`"orientation_source": "auto_rule"`，
  `"orientation_user_confirmed": false`
- `orientation.front_axis` / `orientation.up_axis` 有值，且 `orientation.rule` 写明了判定依据
- `"must_tell_user"` 非空（交付时必须转告用户"方位是自动判的"）
- `check.summary.fail` 为 **0**（本机基准：pass 25 / warn 0 / fail 0 / na 8）
- 产出：
  - `output/powerbank/submission/` 下 **7 张 .jpg**，中文名：`1-主视图` `2-后视图` `3-左视图` `4-右视图` `5-俯视图` `6-仰视图` `7-立体图`
  - `output/powerbank/all_views.dxf`
  - `logs/05_powerbank.json`（33 项自检报告）

> 输出默认落在**桌面「外观专利视图」文件夹**下的 `output/`、`logs/`——
> A 版和 B 版行为一致。桌面不可写时会退回当前工作目录，并在 JSON 的 `note` 里说明。
> OCP 会往 stdout 打 C 层错误信息，**解析 JSON 时务必用 `--quiet` + `--json-out`**。

## 4. 一键式拒绝方位参数（退出码 3）

```bash
CLI auto --step <模型> --mode one_shot --front +Y --quiet
```

期望：退出码 **3**，`error` 说明"一键式不接受 --front / --up"。
这是故意的：否则 agent 可以一边声称一键式、一边自己填方位，等于绕开用户确认。

## 5. 自定义 · 主视图确认（退出码 2）

```bash
CLI auto --step <模型> --mode custom --quiet --json-out o.json
```

期望：退出码 **2**，`o.json` 里：

- `"need": "orientation"`
- `"stage": "main_view"`
- `"selection_page"` 是一个自包含 HTML 文件路径，双击打开可见 6 张候选图（标着正面/背面/左侧/右侧/顶部/底部）
- `"previews"` 含 **6 张**方向缩略图

正确做法：**把 6 张图给用户看，问「哪一张作为主视图」**，不要自己猜。
若 `previews` 为空，按 `error` / `hint` 修（多半是导出目录不可写），**不要自己推断方位**。

## 6. 自定义 · 上方向确认（退出码 2）

拿到主视图方向后，**先只传 `--front`**：

```bash
CLI auto --step <模型> --mode custom --front +Y --quiet --json-out o2.json
```

期望：退出码 **2**，`o2.json` 里：

- `"need": "orientation"`，`"stage": "up_axis"`
- `"main_view": "+Y"`，`"default_up": "+Z"`
- `"selection_page"` 是 HTML 文件路径，双击打开可见 4 张候选（标着正着摆/倒着摆/左倾/右倾）
- `"previews"` 含 **4 张**候选上方向

正确做法：把 4 张图给用户看，问「哪一张符合产品正常摆放时的上方向」。
上方向决定俯视图/仰视图的上下顺序，**弄反会导致附图形式缺陷，不能跳过**。
`default_up` 只在用户明确说"随便/你定"时才可用。

## 7. 自定义 · 多实体引导（退出码 2）

```bash
CLI auto --step <模型> --mode custom --front +Y --up +Z --quiet --json-out s.json
```

期望：若该模型为单实体则直接退出码 0；若为多实体则退出码 2 且 `"need": "solid_selection"`。
此时加 `--solids-filtered` 可声明「用户已确认全量出图」并重跑。

## 8. 自定义 · 全部确认后出图（退出码 0）

```bash
CLI auto --step <模型> --mode custom --front +Y --up +Z --solids-filtered --quiet --json-out c.json
```

期望：退出码 **0**，`"mode": "custom"`，`"orientation_source": "user"`，
`"orientation_user_confirmed": true`，`check.summary.fail` 为 0。

## 9. 出图类命令不替用户猜方位（退出码 2）

```bash
CLI render --step <模型> --quiet          # 不给 --front/--up
CLI run    --step <模型> --quiet
```

期望：退出码 **2**，`"need": "orientation"`，`"stage": "unconfirmed"`。
`run` / `render` / `dxf` / `check` 都是"方位已确认后的（分步）出图"入口；
给了 `--front --up`（或 job.json 里写了方位）才会放行。`analyze` 不在此列。

## 10. 错误路径（退出码 3）

```bash
CLI auto --step 不存在的文件.step --quiet
```

期望：退出码 **3**，JSON 里带 `error`，**不崩栈**。

## 11. 交付物自检

- [ ] 7 张 jpg 尺寸 1772×2598（150×220mm @300DPI）
- [ ] 图内**无任何文字/图号/标注**
- [ ] 只有均匀实线，无虚线/中心线/尺寸线
- [ ] `logs/05_*.json` 中 `fail` 为 0；有 `warn` 必须如实转告用户，不要只说「出好了」

## 12. 导出目录（自定义存放位置）

```bash
CLI config                                     # 看当前导出到哪、这个设置从哪来
CLI config --out-dir "<一个可写目录>"           # 设置并记住
CLI config --reset                             # 忘掉设置，回默认
```

期望：

- `CLI config` 退出码 0，返回 `out_dir` 与 `out_dir_source`（`default` / `config` / `arg` / `env`）
- `config --out-dir` 返回 `"changed": "out_dir"`，之后再 `config` 时 `out_dir_source` 为 `config`
- 此时再出图，产物应落到该目录下的 `output/<产品名>/`、`logs/`
- `config --reset` 后 `out_dir_source` 回到 `default`
